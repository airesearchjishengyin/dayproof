# 六类日常任务：现在怎样验收

本版后台验收只执行代码，不调用 LLM，也不调用 decision model。代码判断不了的部分由用户确认。创建计划时主动使用 AI 仍可选，与后台验收分开。

## 1. 阅读 10 篇最新 game agent 论文并记笔记

**能自动检查笔记交付，不能自动证明认真阅读或理解。**

先固定这次要读的 10 个不同论文链接。“最新”和“game agent 方向”在选论文时由用户或研究工具确认，不由文件计数猜测。`reading_notes` 检查指定目录直接包含的 Markdown 文件，每个指定链接都需有笔记；同一 arXiv 论文的 abs/pdf/不同版本算一篇。多复制几份笔记不能凑够数量。

每篇约定格式如下（省略号要替换成真实正文）：

```markdown
paper: https://arxiv.org/abs/论文编号

## 问题
……至少 30 个非空白字符……

## 方法
……至少 30 个非空白字符……

## 我的理解
……至少 30 个非空白字符……
```

默认结构达标后提示用户确认“我已读完”。若用户明确接受这些笔记产物即为完成依据，可启用自动打勾。字数和标题只能证明结构，重复文字、错误内容仍可能通过，不能把它称为语义检查。

`path` 可以填写实际的 `~/paper`，但须先在原生设置里选择包含该目录的证据根目录。程序不会自动扩大读取范围。本次没有创建论文、目录或真实阅读任务。

## 2. 完成 learning-project 的每日课程

**有明确的当天课程清单或交付文件就能验收；只有聊天中的一句目标还不够。**

例如让执行课程的工具把当天进度写到 `learning-project/progress/2026-10-19.md`：

```markdown
- [ ] 学习第 1 课
- [ ] 完成第 1 课作业
```

使用 `markdown_checklist`，配置 `items: ["学习第 1 课", "完成第 1 课作业"]`。两个条目唯一存在且均变成 `[x]` 时自动完成。条目在代码示例或注释里不算，重复矛盾条目不通过。它代表按课程进度声明验收，不证明听课时长或掌握程度。

也可直接使用已有 `file_exists` 验收指定作业文件，或 `json_equals` 读取课程系统已有状态，不强制项目更换格式。完整非结构化作业是否合格则手动确认。

课程清单和路径是格式示例。实际使用前，需要指定自己的课程安排与作业位置。

## 3. 去取快递

**本期手动。** 没有可读的可信物流/取件记录时不启用自动判断。将来如果有授权可读接口可以适配，并非只有海外邮箱场景才能验证；当前不接微信、淘宝或美团，不登录任何账户。

## 4. 给看好的游戏公司写申请材料邮件

**草稿可以检查；申请质量、附件是否合适由用户确认。** “写邮件”与“发送邮件”是不同目标，本例不发送。

`email_draft` 读取 UTF-8 纯文本 `.eml`：约定的唯一收件人、非空主题、空行后正文至少 100 个非空白字符。示例：

```text
To: jobs@example.com
Subject: 游戏开发岗位申请

这里是申请正文……
```

实际公司邮箱必须由用户指定，不从昵称猜测。本检查不包含附件、HTML、base64/quoted-printable 编码正文或邮箱内未导出的草稿。遇到这些格式保留待确认，不把 MIME 原始数据长度当作邮件内容。

默认结构达标后由用户确认；用户接受上述结构即为交付依据时可以自动打勾。不能仅凭正文够长宣称申请材料完整。本次没有读取邮箱、编写实际申请或发送邮件。

## 5. 接着开发 游戏项目

**需要先约定今天做到哪一步。** 如“README 中保存/加载功能被标成完成”，可以直接复用进度清单检查；若已有 JSON 状态，也可以复用状态检查。

若只要求“今天有开发进展”，需先约定可接受的产物/声明，例如今天的开发记录中勾选“保存/加载完成”。文件有修改、产生一次 commit、打开过编辑器，都不能自行代替任务目标。

当前版支持读取外部测试工具写出的 JSON，但不会主动执行 shell、构建或测试，也没有 Git 差异检查器。需要由用户指定游戏项目的路径和阶段目标。

## 6. Claude 使用官方免费账号，不用第三方 API

**目前整体手动确认，不能只靠查配置自动完成。**

“未发现第三方配置”和“官方免费账号实际可用”是不同条件。配置、进程环境或登录信息都可能只覆盖一部分，不能用没有 API key 代替实际使用成功。

验收时需明确是 Claude 网页/桌面应用还是 Claude Code，并核对对应产品当前的免费账户支持。不能预先承诺免费 Claude 账号一定支持 Claude Code。在目标客户端确认官方账号登录、实际请求可用、没有走第三方后，由用户手动勾选。

本次未核查 Anthropic 当前套餐政策，也未检查/修改任何 Claude 配置或账号。不提供绕过套餐限制的检查器。

## 已落地范围

- 原生与开发界面可配置 `markdown_checklist`、`reading_notes`、`email_draft`。
- 旧 `llm` 规则保留兼容读取，但验收函数直接返回待人工确认，调度器不轮询它；即使旧规则的 `autoComplete=true` 也不调用模型。
- 笔记和邮件的 `autoComplete` 默认关闭。手动最终确认是默认能力，不是额外模型费用。
- 所有读取仍受证据根目录及单文件 32 KB 限制；笔记目录只扫描直接子文件，超过 1,000 项报错，建议每日专用目录。
- README 自动复选框验收仅按用户认可的声明打勾。代码检查不承诺内容质量。

这里是检查能力和示例，不是这六件任务的完成报告；没有导入用户真实任务，也未替用户完成课程、阅读、申请或账户配置。
